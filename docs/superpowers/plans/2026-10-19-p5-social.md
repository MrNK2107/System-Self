# P5 — Social Layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real multiplayer per PRD §14–§16: silent rivals matched from real users (with ghost rivals for cold start), identity control, following, clans with dead-weight handling and weekly raids, named challenges, Shame Mode, and the adherence design's Party of Two.

**Architecture:** All social state is in Postgres and computed server-side. Weekly/daily social jobs run in the P2 worker (`runWorkerTick` gains a `runSocialJobs` step guarded by `pg_try_advisory_lock` per job key so one instance runs each job). Clients poll (React Query `refetchInterval` 60 s on social screens). What a viewer can see of another user goes through one function, `projectUser(viewer, subject, relation)`, so identity rules live in one place.

**Tech Stack:** same as P2–P4.

**Spec:** PRD §14 (Rivalry), §15 (Clans), §16 (Identity & Following), §11 Layer 3 (Shame Mode); architecture spec §5 (cold start / ghost rivals); adherence spec 3.4 (Party of Two).

## Global Constraints

- **Nobody sees another user's hidden score, quest content or log content, ever.** Allowed fields per relation are defined in `projectUser` (Task 1) and nowhere else.
- Identity settings: `anonymous` → codename only everywhere, no external clan affiliation; `semi-public` (default) → username inside the clan, codename to rivals and public; `public` → username everywhere. Inside a clan, members always see usernames (PRD §16).
- Codenames: per-user public codename `USER // <WORD>-<N>` (word list in engine, N 1–9) generated at onboarding (store on `profiles.publicCodename`); per-rival-assignment codename `RIVAL // <WORD>-<N>`.
- Rivals: 3 slots per user. Real rivals only when the user is rank ≥ D (PRD); before that all slots are ghosts. Matching: same tier, |hidden − hidden| ≤ 5 preferred, widening to ≤ 10; candidate active (a log) in the last 7 days; not already assigned; not blocked. Re-match every 30 days per slot or immediately on the user's rank change. Ghosts fill unmatched slots.
- Ghost drift per day (same as the old client): trajectory up `0.35 + r*0.45`, down `−(0.25 + r*0.35)`, stable `(r − 0.5)*0.18`; per domain `base*(0.4 + r*0.6)`, clamp 1..99; seeded RNG per (ghostId, date) so it is deterministic. Ghosts are labelled `GHOST` in API payloads (`isGhost: true`); the UI shows a small `SIM` tag.
- Rival pressure: when a rival's domain score passes the user's (it was ≤ and is now >) at the user's rollover, one notice `rival_passed` `{ codename, domain }` and one line in the next morning briefing; no repeat until the order flips back.
- Clans: hard size limits 8–30. A clan with < 8 members is `forming` (no raids, not ranked). Creation requires PRO (P7; until then gate on `entitlements` stub `isPro(userId)` that returns false unless admin-granted) and a verified email. One clan per user. Clan name 3–24 chars `^[A-Za-z0-9 _-]+$`, unique case-insensitive; tag 2–5 uppercase letters.
- Clan Score (daily at 00:30 UTC): mean hidden score of members active in the last 5 days (inactive members excluded) + raid bonus points accumulated this month; Clan Rank = global order by clan score among `active` (≥ 8) clans.
- Dead weight: a member with ≥ 5 consecutive inactive local days is `flagged`; only the leader can remove a flagged member (non-flagged members can't be kicked; leaders can transfer leadership).
- Raids: weekly, Monday 00:00 UTC → Sunday 23:59 UTC. Each active clan is grouped with 1–3 other active clans of the nearest clan rank (groups of 2–4). Type rotates by ISO week number mod 4: `domain` (count of MIND logs), `discipline` (clan-wide quest completion rate), `body` (count of BODY logs + gym sessions), `score` (sum of members' hidden-score change over the week). Result at Sunday 23:59 UTC: winner gets `+2.0 × activeMemberCount` clan score bonus; notices `raid_result` to all members; a dispatch text in the PRD format, e.g. `RAID RESULT — WEEK {n}. Your clan ranked {pos} of {count}. {metric}: {value}. Rival clan: {value}. Gap: {gap}.` (AI-rewritten if available, template otherwise; no emoji).
- Named challenges (PRO): to a followed user or a clan member; `domain`, timeframe 3/7/14/30 days, metric = domain score gain over the window; accept/ignore within 48 h; ignoring is visible to the challenger (`Challenge ignored. Logged.`); winner `+3.0` DISCIPLINE, loser `−1.5` DISCIPLINE through `applyChanges` with reason `challenge` (draw: nothing). Max 3 open challenges per user.
- Rival challenges (free, existing feature): against an assigned rival, one domain, 7 days, gain vs gain; record wins/losses/draws; **no score effect**.
- Shame Mode (PRO, opt-in per quest): if that quest fails, all clan members get notice `shame` `{ handle, questTitle }` rendered `{handle} failed to complete: {questTitle}. Logged.` (handle = username in clan). Users without a clan can't enable it.
- Party of Two: one duo per user; invite by username; partner sees check-ins (`going_now`, `checked_in`, `done`) with timestamps, last 7 days; a nudge (`going now`) at most 3 per day per sender. No score effect. Identity: inside a duo both see usernames.
- Blocking: any user can block another (rival matching, follows, challenges, duo and clan invites all respect blocks). Report endpoint stores reports for admin review.

## Review Focus

1. **Identity leaks** — an `anonymous` user's username never appears in rival, follower, leaderboard or raid payloads (test with a deep scan of responses). (Task 1)
2. **Cold start** — a lone user at rank B gets 3 ghost rivals and a working rivals screen. (Task 2)
3. **Clan at exactly 30** — the 31st join → 409 `{ code: "clan_full" }`; the leader leaving with members remaining must transfer first → 409 `{ code: "leader_must_transfer" }`. (Task 4)
4. **Raid with an odd number of clans** — 5 active clans → groups of 3 and 2 (no clan left out); a single active clan → no raid that week. (Task 5)
5. **Challenge expiry with a deleted opponent** — the challenge is voided and no score changes apply. (Task 6)
